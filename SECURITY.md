# Security Policy

## Supported Versions

This project is a standalone, client-side WebGL implementation. We actively maintain and apply security fixes to the latest deployment branch.

| Version | Supported          |
| ------- | ------------------ |
| 1.0.x   | :white_check_mark: |
| < 1.0   | :x:                |

## Reporting a Vulnerability

We take the security and integrity of this independent simulation project seriously. Since this software is an entirely browser-based frontend implementation built on standard Three.js frameworks, security concerns generally focus on client-side script optimizations or interface stability.

If you discover a potential security vulnerability or asset policy concern, please follow these reporting procedures:

1. **Do Not Open a Public Issue:** To prevent unnecessary disruption or exploitation risks, do not file public bug reports or comment threads regarding discovered security flaws.
2. **Private Disclosure:** Please notify the repository administrator privately by opening a secure communication or reviewing the repository profile for contact directions.
3. **Response Timeline:** We aim to acknowledge your private report within 48 hours and outline an appropriate patch or resolution path immediately if a valid structural vulnerability is verified.

## Safety & Scope Principles

* **Fictional Project Boundary:** This software is an independent, fictional ambient simulation. It does not interface with, control, or mirror any real cloud infrastructure, backend authentication protocols, or third-party enterprise data systems.
* **Asset Safety:** We actively monitor our codebase to ensure no real corporate trademarks, restricted brand names, or private credentials are included within the scripts or asset layers.
